# System Integration

localtool dns automatically detects and integrates with your system's DNS resolver.

## Detection

Run `localtool dns detect` to see what your system is running:

```
Port Usage:
  Port 53     dnsdist
  Port 5053   dnscrypt-proxy
  Port 5353   avahi-daemon
  Port 5354   (free) ✓

DNS Services:
  ✓ dnsdist
  ✓ dnscrypt-proxy
  ✓ avahi-daemon

Upstream: 127.0.0.1:5053
```

## Supported setups

### dnsdist

dnsdist is detected and a Lua routing snippet is generated by `init`. The routing rule forwards queries for your custom TLDs (`.test`, `.dev`, `.local`) to dnsmasq on port 5354 while everything else goes to the normal upstream.

**Important:** After adding new domains, restart dnsdist (or query dnsmasq directly via `dig @127.0.0.1 -p 5354`) to avoid NXDOMAIN caching.

```bash
sudo systemctl restart dnsdist
# or bypass cache:
dig myapp.test @127.0.0.1 -p 5354
```

### systemd-resolved

`init` runs `resolvectl` commands to route your custom TLDs to the dnsmasq instance. systemd-resolved handles caching, so new entries are available immediately.

### dnscrypt-proxy

Detected as upstream. Works with or without dnsdist in front.

### bind9

Configure a forwarding zone in `named.conf` to point your custom TLDs to `127.0.0.1:5354`.

### None / Direct

If no resolver is detected, `/etc/resolv.conf` is configured to point to `127.0.0.1` with dnsmasq as the sole resolver.

## Port management

local-dns always uses **port 5354** to avoid conflicts. If another service is using 5354, `init` will warn you.
